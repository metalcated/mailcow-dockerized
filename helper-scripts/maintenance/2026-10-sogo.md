# October 2026: SOGo security update

Status: prepared for server validation after PHP and Nginx deployment checks.
Source baseline: `f42caf12`. The image moves from `5.12.9-1` to `5.12.12-1`,
pinned to multi-architecture digest
`sha256:dddbb48cbfbd0dd984953fd69e45ed3b33d157665f0ac3df9c0237876ebe8ae0`.
`SOGO_IMAGE` provides an image-only rollback override.

[Upstream release](https://github.com/mailcow/mailcow-dockerized/pull/7536)
fixes an IDOR and the 5.12.11 mail sorting regression. The earlier
[5.12.11 release](https://github.com/Alinto/sogo/releases/tag/SOGo-5.12.11)
also fixes XSS and password-reset poisoning.

## Compatibility boundaries

The pulled 5.12.9 and 5.12.12 images have identical bootstrap, entrypoint, and
supervisor configuration. This avoids importing the stale legacy Dockerfile's
different view/trigger preparation. Confirm those hashes against the actual
running server image before recreating SOGo.

The new `data/conf/sogo/plist_ldap.sh` adapter renders the existing legacy
`plist_ldap` template using the domain and GAL arguments that both packaged
bootstraps already expect. The template itself is unchanged. If a server has
an untracked customized `plist_ldap.sh`, Git must stop rather than overwrite it;
review that customization before deployment. Do not disable LDAP certificate
verification globally. Custom LDAPS configurations need their own certificate
validation check because the newer SOPE verifies LDAP certificates.

No Mailcow schema source/version, SOGo configuration, authentication profile,
proxy template, scheduler labels, theme asset, or other service image changes.
SOGo's existing startup still checks schema, drops its old password-update
trigger on the master, generates a profile/key, patches navigation, and syncs
web assets. A fresh SOGo login may be needed after restart. Native SOGo behavior
is not a proof that persistent tables can never change: preserve a database
dump and shared web assets before deployment, in addition to the server snapshot.

## Local evidence

The combined suite seals prior PHP/Nginx source stages and verifies the current
compose changes only the SOGo image. Offline fixtures run each image's real
bootstrap with stubbed SQL, socket probes, and daemon handoff; parsed profiles
match except the random encryption key, including SQL source, IMAP/SMTP/Sieve
targets, proxy authentication, and copied custom theme hashes. The fixture
tests LDAP argument handling and the replica no-trigger-write path. Library
loading, embedded version, and ActiveSync module presence are checked too.
This is not authenticated browser/Outlook or real SOGo database validation.

```sh
MAILCOW_TEST_PHP_RUNTIME=1 MAILCOW_TEST_PHP_DATABASE=1 MAILCOW_TEST_NGINX_RUNTIME=1 MAILCOW_TEST_SOGO_RUNTIME=1 MAILCOW_TEST_PLATFORM=linux/arm64 python3 -W error -m unittest discover -s helper-scripts/tests -p 'test_*_legacy_update.py' -v
```

## Server application

Run the following only from the established checkout on the maintenance branch.
It stops before replacement if the startup hashes differ or preflight fails.
Preflight must override the SOGo entrypoint: do not run a second full bootstrap
against the production database while the old instance is still running.

```sh
(
  set -eu
  set -o pipefail
  umask 077
  cd /opt/mailcow-dockerized
  test "$(git branch --show-current)" = 'feature/october-2026-security-backports'
  RECOVERY_DIR="backups/sogo-pre-october-2026-$(date +%Y%m%d-%H%M%S)"
  mkdir -p "$RECOVERY_DIR"
  chmod 700 "$RECOVERY_DIR"
  cp -a data/conf/sogo "$RECOVERY_DIR/sogo-conf"
  SOGO_CONTAINER=$(docker compose ps -q sogo-mailcow)
  test -n "$SOGO_CONTAINER"
  SOGO_ID=$(docker inspect --format '{{.Image}}' "$SOGO_CONTAINER")
  SOGO_ROLLBACK="mailcow-sogo-rollback:pre-october-2026-$(date +%Y%m%d%H%M%S)"
  docker image tag "$SOGO_ID" "$SOGO_ROLLBACK"
  printf '%s\n' "$SOGO_ROLLBACK" > "$RECOVERY_DIR/rollback-image.txt"
  printf '\nRecovery: %s\nRollback: %s\n' "$RECOVERY_DIR" "$SOGO_ROLLBACK"
  docker compose exec -T mysql-mailcow sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mariadb-dump --user="$MYSQL_USER" --single-transaction --no-tablespaces --routines --events --triggers "$MYSQL_DATABASE"' | gzip > "$RECOVERY_DIR/database.sql.gz"
  docker compose exec -T sogo-mailcow tar -C /sogo_web -czf - . > "$RECOVERY_DIR/sogo-web.tar.gz"
  docker compose exec -T sogo-mailcow sha256sum /bootstrap-sogo.sh /docker-entrypoint.sh /etc/supervisor/supervisord.conf > "$RECOVERY_DIR/old-startup.sha256"
  git pull --ff-only origin feature/october-2026-security-backports
  docker compose config --quiet
  SOGO_TARGET=$(docker compose config --images sogo-mailcow | awk '/^ghcr[.]io\/mailcow\/sogo[:@]/')
  test "$SOGO_TARGET" = 'ghcr.io/mailcow/sogo:5.12.12-1@sha256:dddbb48cbfbd0dd984953fd69e45ed3b33d157665f0ac3df9c0237876ebe8ae0'
  docker pull "$SOGO_TARGET"
  docker compose run --rm --no-deps --entrypoint sha256sum sogo-mailcow /bootstrap-sogo.sh /docker-entrypoint.sh /etc/supervisor/supervisord.conf > "$RECOVERY_DIR/new-startup.sha256"
  cmp "$RECOVERY_DIR/old-startup.sha256" "$RECOVERY_DIR/new-startup.sha256"
  docker compose run --rm --no-deps --entrypoint bash sogo-mailcow -ec 'bash -n /bootstrap-sogo.sh; test -x /etc/sogo/plist_ldap.sh; bash -n /etc/sogo/plist_ldap.sh; /etc/sogo/plist_ldap.sh example.invalid YES >/dev/null; test -d /usr/local/lib/GNUstep/SOGo/ActiveSync.SOGo; grep -aom1 "5[.]12[.]12" /usr/local/sbin/sogod /usr/local/lib/sogo/libSOGo.so.5'
  docker compose up -d --no-deps --force-recreate sogo-mailcow
  READY=0
  for ATTEMPT in $(seq 1 45); do
    if docker compose exec -T sogo-mailcow nc -z 127.0.0.1 20000 2>/dev/null; then
      READY=1
      break
    fi
    sleep 2
  done
  docker compose logs --since=3m --tail=100 sogo-mailcow
  test "$READY" -eq 1
  docker compose exec -T sogo-mailcow supervisorctl status
  docker compose ps sogo-mailcow nginx-mailcow php-fpm-mailcow dovecot-mailcow postfix-mailcow
  docker compose exec -T mysql-mailcow sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mariadb --user="$MYSQL_USER" "$MYSQL_DATABASE" --batch -e "SELECT application, version FROM versions;"'
  printf '\nRecovery: %s\nRollback: %s\n' "$RECOVERY_DIR" "$SOGO_ROLLBACK"
)
```

The service can take longer to initialize on a large installation. If readiness
times out, inspect logs rather than repeatedly restarting it. Confirm fresh
SOGo SSO, folder/message loading, mail sorting, draft attachment save/reopen,
send/receive, calendar/address book, preview theme and dialogs. Test existing
Outlook sync and DAV/EAS when used. No working Outlook account should be removed.
Nginx serves the refreshed shared resources without an image update/restart.

## Rollback

Read the saved tag from the printed recovery directory and use `SOGO_IMAGE`
as an environment override for `docker compose up -d --no-deps --force-recreate
sogo-mailcow`. This keeps PHP/Nginx at their accepted versions. The previous
image's bootstrap restores its web resources, and the LDAP adapter works with
both versions. A shell override is temporary; coordinate a durable rollback
configuration before subsequent compose operations. Do not automatically import
the database dump or restore the server snapshot: inspect the failure and scope
any data restore to avoid discarding mail or changes made after the backup.
