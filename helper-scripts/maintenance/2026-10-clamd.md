# October 2026: ClamAV security update

Status: prepared for server validation after the accepted PHP, Nginx, and SOGo
updates. Source baseline: `4d1a89d2`. Only the ClamAV service image changes.

The old `ghcr.io/mailcow/clamd:1.71` image contains ClamAV 1.4.2. The replacement
`1.4.6-1` image is pinned to multi-architecture digest
`sha256:0d512b3a179c5f97e6f3132d1f88d9ec72c456fc6f7ba32a664ed4327fbd1436`.
`CLAMD_IMAGE` permits an image-only rollback override.

The [ClamAV 1.4.6 release](https://github.com/Cisco-Talos/clamav/releases/tag/clamav-1.4.6)
fixes parser memory-safety issues including CVE-2026-20345 and CVE-2026-20339,
as well as PDF, Mach-O, XAR, and STATS fixes. The image version matches the
[upstream Mailcow update](https://github.com/mailcow/mailcow-dockerized/pull/7415).
This does not assert that every advisory is exploitable in this configuration.

## Compatibility and validation

The actual old/new packaged `/clamd.sh` and `clamdcheck.sh` are byte-identical.
Scan limits, whitelist, signature volume, Rspamd endpoint `clamd:3310`, and all
other services remain unchanged. No SQL schema, mail data, authentication,
proxy, or theme changes are included. The existing startup refreshes antivirus
definitions and normalizes the whitelist; these are not new migration steps.

Local tests use disconnected containers and a synthetic signature database to
start the real daemon with the existing configuration, scan clean and matching
streams, and verify readiness failure without a daemon. These do not validate
production signatures, resource requirements, or real mail delivery. The server
handoff checks a clean stream and a PING from the existing Rspamd container.
It backs up the antivirus definition volume and configuration before replacement.

## Server application

Restarting only ClamAV briefly interrupts antivirus checks. Depending on the
existing Rspamd failure policy, concurrent mail may be deferred or not scanned;
do not intentionally submit mail until readiness and Rspamd connectivity pass.
No dependencies are recreated. Do not disable antivirus or relax scan policy.
The preflight is a standalone container with no network or persistent volumes.

```sh
(
  set -eu
  set -o pipefail
  umask 077
  cd /opt/mailcow-dockerized
  test "$(git branch --show-current)" = 'feature/october-2026-security-backports'
  RECOVERY_DIR="backups/clamd-pre-october-2026-$(date +%Y%m%d-%H%M%S)"
  mkdir -p "$RECOVERY_DIR"
  chmod 700 "$RECOVERY_DIR"
  CLAMD_CONTAINER=$(docker compose ps -q clamd-mailcow)
  test -n "$CLAMD_CONTAINER"
  docker compose exec -T clamd-mailcow sh -ec 'case "${SKIP_CLAMD:-n}" in y|Y|yes|YES) echo "ClamAV is disabled; stop for review"; exit 1;; esac'
  CLAMD_ID=$(docker inspect --format '{{.Image}}' "$CLAMD_CONTAINER")
  CLAMD_ROLLBACK="mailcow-clamd-rollback:pre-october-2026-$(date +%Y%m%d%H%M%S)"
  docker image tag "$CLAMD_ID" "$CLAMD_ROLLBACK"
  printf '%s\n' "$CLAMD_ROLLBACK" > "$RECOVERY_DIR/rollback-image.txt"
  cp -a data/conf/clamav "$RECOVERY_DIR/clamav-conf"
  docker compose exec -T clamd-mailcow tar -C /var/lib/clamav -czf - . > "$RECOVERY_DIR/clamav-db.tar.gz"
  gzip -t "$RECOVERY_DIR/clamav-db.tar.gz"
  docker compose exec -T clamd-mailcow sha256sum /clamd.sh /usr/local/bin/clamdcheck.sh > "$RECOVERY_DIR/old-startup.sha256"
  printf '\nRecovery: %s\nRollback: %s\n' "$RECOVERY_DIR" "$CLAMD_ROLLBACK"
  git pull --ff-only origin feature/october-2026-security-backports
  docker compose config --quiet
  CLAMD_TARGET=$(docker compose config --images clamd-mailcow | awk '/^ghcr[.]io\/mailcow\/clamd[:@]/')
  test "$CLAMD_TARGET" = 'ghcr.io/mailcow/clamd:1.4.6-1@sha256:0d512b3a179c5f97e6f3132d1f88d9ec72c456fc6f7ba32a664ed4327fbd1436'
  docker pull "$CLAMD_TARGET"
  docker run --rm --pull=never --network=none --entrypoint sha256sum "$CLAMD_TARGET" /clamd.sh /usr/local/bin/clamdcheck.sh > "$RECOVERY_DIR/new-startup.sha256"
  cmp "$RECOVERY_DIR/old-startup.sha256" "$RECOVERY_DIR/new-startup.sha256"
  docker run --rm --pull=never --network=none --mount "type=bind,src=$PWD/data/conf/clamav,dst=/etc/clamav,readonly" --entrypoint sh "$CLAMD_TARGET" -ec 'clamd -V; clamconf -n >/dev/null; bash -n /clamd.sh'
  docker compose up -d --no-deps --force-recreate clamd-mailcow
  READY=0
  for ATTEMPT in $(seq 1 90); do
    if docker compose exec -T clamd-mailcow clamdscan --ping 1 >/dev/null 2>&1; then
      READY=1
      break
    fi
    sleep 2
  done
  docker compose logs --since=5m --tail=70 clamd-mailcow
  test "$READY" -eq 1
  printf 'Mailcow clean scanner connectivity test.\n' | docker compose exec -T clamd-mailcow clamdscan --stream --no-summary -
  docker compose exec -T rspamd-mailcow timeout 10 bash -ec 'exec 3<>/dev/tcp/clamd/3310; printf "nPING\n" >&3; IFS= read -r REPLY <&3; test "$REPLY" = PONG; printf "Rspamd to ClamAV: %s\n" "$REPLY"'
  docker compose exec -T clamd-mailcow clamd -V
  docker compose ps clamd-mailcow rspamd-mailcow sogo-mailcow dovecot-mailcow postfix-mailcow
  printf '\nRecovery: %s\nRollback: %s\n' "$RECOVERY_DIR" "$CLAMD_ROLLBACK"
)
```

Then send and receive a normal test message with an attachment, check for the
ClamAV `instream ... OK` result, and confirm no scanner connection errors in
Rspamd. Do not send a malware test string to a real recipient. A socket PING and
clean direct scan alone do not prove Rspamd actually scanned the test email.
If readiness times out, inspect logs; do not repeatedly restart or disable scans.

## Rollback

Read the saved tag from the recovery directory and set `CLAMD_IMAGE` to it for
`docker compose up -d --no-deps --force-recreate clamd-mailcow`. This changes only
the scanner. Do not restore SQL, mail volumes, or the server snapshot for a
scanner-only issue. Do not automatically overwrite newer signature data with the
backup; review any signature compatibility failure first. An image override in
the shell is temporary and must be accounted for before later compose commands.
