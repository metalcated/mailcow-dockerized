Status: prepared for server validation. PHP deployment checks have passed on
the server; its live login, Outlook reconnect, and mail-flow acceptance must
pass before Nginx is recreated. Do not infer acceptance from container health.

Source baseline: `5cabaf3c`. The only service changes in this stage are:

- Pin Nginx `1.30.6-1` to multi-architecture digest
  `sha256:68697b99f272527dc38bbfb4c8cf217c02dffc7bc0a0b3b19b0c5256eda2aef4`.
- Allow `NGINX_IMAGE` as an image-only rollback override.
- Mount the unchanged fork's `bootstrap.py` read-only. This preserves its
  `DISABLE_IPv6` input and pairs it with the unchanged legacy templates instead
  of importing the upstream renderer's `ENABLE_IPV6` behavior.

No routes, ports, proxy headers, SOGo authentication, Autodiscover, PHP settings,
database code, or other service images change.
[Upstream security release](https://github.com/mailcow/mailcow-dockerized/pull/7535).

## Validation

The Nginx regression suite compares the complete compose configuration to the
PHP-stage baseline and permits only the image and renderer mount changes.
Offline tests generate fixture certificates and compare the old/new image's
rendered configurations byte for byte with IPv6 enabled, disabled, and PROXY
protocol enabled. Both images must pass `nginx -t`. These are local fixtures,
not a test of the production reverse proxy, certificate, or Outlook client.

```sh
MAILCOW_TEST_PHP_RUNTIME=1 MAILCOW_TEST_PHP_DATABASE=1 MAILCOW_TEST_NGINX_RUNTIME=1 MAILCOW_TEST_PLATFORM=linux/arm64 python3 -W error -m unittest discover -s helper-scripts/tests -p 'test_*_legacy_update.py' -v
```

## Server preflight

Use one block, stop on failure, and do not discard the generated Postfix/Redis
settings. The private validation configuration is copied under `backups` so
rendering the new config cannot modify the running Nginx bind mount. Its
one-off container publishes no ports. It uses the normal entrypoint with
`nginx -t` as its command, so empty PHP/SOGo/Rspamd host variables receive the
same defaults as production before rendering. Do not call the renderer directly
with `--entrypoint sh`: Compose exports these variables as empty strings.

```sh
(
  set -eu
  set -o pipefail
  umask 077
  cd /opt/mailcow-dockerized
  RECOVERY_DIR="backups/nginx-pre-october-2026-$(date +%Y%m%d-%H%M%S)"
  mkdir -p "$RECOVERY_DIR/conf.d"
  chmod 700 "$RECOVERY_DIR"
  cp -a data/conf/nginx/. "$RECOVERY_DIR/conf.d/"
  git rev-parse HEAD > "$RECOVERY_DIR/previous-commit.txt"
  NGINX_CONTAINER=$(docker compose ps -q nginx-mailcow)
  test -n "$NGINX_CONTAINER"
  NGINX_ID=$(docker inspect --format '{{.Image}}' "$NGINX_CONTAINER")
  NGINX_ROLLBACK="mailcow-nginx-rollback:pre-october-2026-$(date +%Y%m%d%H%M%S)"
  docker image tag "$NGINX_ID" "$NGINX_ROLLBACK"
  printf '%s\n' "$NGINX_ROLLBACK" > "$RECOVERY_DIR/rollback-image.txt"
  git pull --ff-only origin feature/october-2026-security-backports
  docker compose config --quiet
  NGINX_TARGET=$(docker compose config --images nginx-mailcow | awk '/^ghcr[.]io\/mailcow\/nginx[:@]/')
  test "$NGINX_TARGET" = 'ghcr.io/mailcow/nginx:1.30.6-1@sha256:68697b99f272527dc38bbfb4c8cf217c02dffc7bc0a0b3b19b0c5256eda2aef4'
  docker pull "$NGINX_TARGET"
  docker run --rm --network none --entrypoint nginx "$NGINX_TARGET" -v
  docker compose run --rm --no-deps --volume "$PWD/$RECOVERY_DIR/conf.d:/etc/nginx/conf.d" nginx-mailcow nginx -t
  printf '\nRecovery directory: %s\nRollback image: %s\n' "$RECOVERY_DIR" "$NGINX_ROLLBACK"
  docker compose exec -T nginx-mailcow nginx -v
)
```

Expected new binary: `nginx/1.30.6`; configuration syntax must pass. The running
production binary remains `1.30.4` at this point. If Git or any validation fails,
stop and review output; do not recreate Nginx.

## Apply after preflight and PHP client acceptance

```sh
(
  set -eu
  cd /opt/mailcow-dockerized
  docker compose up -d --no-deps --force-recreate nginx-mailcow
  sleep 2
  docker compose logs --since=3m --tail=70 nginx-mailcow
  docker compose exec -T nginx-mailcow nginx -t
  docker compose exec -T nginx-mailcow nginx -v
  docker compose ps nginx-mailcow php-fpm-mailcow dovecot-mailcow postfix-mailcow sogo-mailcow
)
```

Expect a brief HTTP/SSO interruption; IMAP/SMTP processes are not intentionally
restarted. Verify fresh Mailcow login, quarantine, SOGo SSO/theme, the actual
external reverse-proxy URL, and existing Outlook reconnect/send/receive. Check
DAV/EAS if used. Do not delete a working Outlook account to test new-account
setup, which is a known baseline problem.

## Image-only rollback

Read the saved rollback tag from the printed recovery directory, then set
`NGINX_IMAGE` to that tag in the same shell used for the following commands.
This leaves PHP 8.2.35 and the legacy renderer in place.

```sh
test -n "$NGINX_IMAGE"
docker image inspect "$NGINX_IMAGE" --format '{{.Id}}'
NGINX_IMAGE="$NGINX_IMAGE" docker compose up -d --no-deps --force-recreate nginx-mailcow
docker compose exec -T nginx-mailcow nginx -t
docker compose exec -T nginx-mailcow nginx -v
```

Stop after rollback and coordinate a durable configuration before a later
compose operation: a shell-only override is not persistent. Keep the private
recovery directory and old image until the whole maintenance cycle is accepted.
