# October 2026: Redis 7.4 security update

Source baseline: `2a8e8973`. Status: prepared for server validation after ClamAV.
Only the Redis image changes, from 7.4.8 to 7.4.12, pinned to multi-architecture
digest `sha256:338fbfc036dc5517ac0b04d6de21521085935336e565f223406180e9d84166e2`.
`REDIS_IMAGE` permits an image-only rollback override. The existing startup,
password, restricted quota-notifier ACL, network, and data volume are unchanged.

The [Redis 7.4 release notes](https://redis.io/docs/latest/operate/oss_and_stack/stack-with-enterprise/release-notes/redisce/redisce-7.4-release-notes/)
document memory-safety and ACL fixes after 7.4.8. The official
[7.4.12 security patch](https://github.com/redis/redis/releases/tag/7.4.12)
adds a cluster-bus buffer-overflow fix. That additional cluster-only issue is not
exposed by this standalone configuration; the earlier same-series fixes are the
main reason to update. Mailcow master currently uses 7.4.11; this deliberately
uses the subsequent official Redis patch, not Redis 8 or a replacement engine.

## Data and related workflows

Redis stores important operational state, including DKIM keys and filtering
data; it is not disposable cache. The helper exports a consistent online RDB
snapshot into a private recovery directory and validates it with the new image.
It does not flush keys, replace the live volume, restore a backup, rotate a
password, migrate MariaDB, or modify client authentication/routing. A snapshot
is a point-in-time backup, not a promise to preserve later writes if restored.

Restarting Redis briefly interrupts its clients, including web, filtering and
ban-event consumers. Netfilter may reconnect or restart automatically under its
existing policy; its image and firewall backend are not changed. The helper
requires an existing F2B_CHANNEL subscriber and waits for subscriptions to
return afterward. This is not a full proof of firewall banning functionality.
Do not restart all services or change UFW/iptables to repair a Redis issue.

The helper intentionally stops for replica, cluster, AOF, nonstandard snapshot
paths, remote PHP Redis, or unexpected version-series configurations. Such
installations need their own migration and backup procedure.

Local fixture tests cover existing authentication/ACLs, data types and expiry,
Lua, pub/sub, PHP/Rspamd clients, and old-new-old RDB persistence. These are not
production-data/browser/Outlook validation. Online backup and a candidate RDB
check are performed before the live service is replaced. Do not run a second
full Redis service on its production static address for preflight.

## Server application

After normal attachment mail delivery has passed following ClamAV:

```sh
(
  set -eu
  set -o pipefail
  cd /opt/mailcow-dockerized
  test "$(git branch --show-current)" = 'feature/october-2026-security-backports'
  git pull --ff-only origin feature/october-2026-security-backports
  bash helper-scripts/maintenance/2026-10-redis.sh
)
```

Expect Redis 7.4.12, PHP and Rspamd PONG responses, and restored F2B_CHANNEL
subscriptions. Then verify fresh Mailcow/SOGo access, ordinary attachment
send/receive, existing Outlook sync, and no continuing Redis errors in clients.
Keep the snapshot, private recovery directory, and rollback images overnight.
If a check fails after replacement, inspect logs and identify whether Redis or
one client failed; do not automatically restore old data or the server snapshot.
The helper prints a narrow old-image rollback command on failure. A shell image
override is temporary and must be made durable before subsequent compose work.
