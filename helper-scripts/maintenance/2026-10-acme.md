# October ACME compatibility stage

Prepared, not deployed. Parent: `931548ae` (completed October images plus checkout-permission safeguards).
Branch: `feature/october-2026-acme-legacy-compat`.

## Scope

- Only ACME changes: image 1.92 to digest-pinned 1.98, with an `ACME_IMAGE` rollback override.
- Three existing fork scripts are mounted read-only. They remain byte-identical to the accepted fork: HTTP-01, domain selection, contact handling, account/domain keys, renewal threshold, and reload behavior.
- The stock 1.98 orchestration requires the absent `mta_sts` table and enables new DNS-01 behavior. Neither is imported. No schema migration, DNS credentials, SAN expansion, authentication, Nginx path, Dovecot, Postfix, or Outlook changes.
- Offline fixtures test the real candidate's OpenSSL/Bash/acme-tiny CLI with a fake CA: creation, unchanged certificate, forced and near-expiry renewal, SAN change, key mismatch rejection, CA error preservation, and unsupported key type. They do not test Let's Encrypt issuance or the production HTTP-01 path.
- This updates the image dependencies, not every possible vulnerability in retained scripts. Do not describe it as complete CVE clearance.

## Apply After Reviewing Preflight

`bash helper-scripts/maintenance/2026-10-acme.sh apply` stops and recreates **only ACME**, preserves the old image and a private snapshot of all certificate/account files, and verifies the three running script hashes. It never forces renewal. On a normal cycle, the existing certificate logic can still renew if DNS validation changes the selected domains; renewal can reload Nginx, Postfix, and Dovecot. Choose a window allowing those normal reloads. A five-second running-state check is not renewal proof.

Afterward, inspect `docker compose logs --since=5m --tail=100 acme-mailcow`, require Redis/database/Nginx/resolver initialization to complete, verify certificate names/expiry and normal mail/UI access, and confirm no missing-table errors. Do not paste private keys or full environments. Watchdog checks must remain healthy. Do not advance on a renewal or delivery failure.

## Recovery

Read `backups/acme-pre-october-2026-*/rollback-image.txt` from the exact recovery directory printed by apply. Set `ACME_IMAGE` to that saved local tag and recreate only ACME with `docker compose up -d --no-deps --force-recreate acme-mailcow`. All three mounted scripts are identical for old/new images. Leave certificate files in place; restoring a stale certificate backup can undo a valid renewal. Review that separately if necessary. Keep the snapshot and recovery directory private.
